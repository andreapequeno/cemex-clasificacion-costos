6. AUTENTICACIÓN Y LISTA DE CORREOS AUTORIZADOS
============================================================

La aplicación está configurada para cerrar el acceso si no encuentra una lista
de correos autorizados. Utiliza inicio de sesión OIDC de Streamlit con Google
como proveedor de ejemplo.

La autenticación OIDC requiere configurar un cliente OAuth en Google Cloud
Console y registrar la URL de callback que indique el proveedor/servicio de
despliegue. Si CEMEX utiliza Microsoft Entra ID, conviene solicitar a TI que
configure el proveedor corporativo y valide la política de acceso. No asumas
que cualquier cuenta Gmail o Microsoft está autorizada.

En el entorno local, crea:
.streamlit/secrets.toml

Ejemplo de estructura (usa valores reales proporcionados/configurados por el
administrador; nunca compartas este archivo):

[auth]
redirect_uri = "https://TU-DOMINIO-O-APP/oauth2callback"
cookie_secret = "REEMPLAZAR_POR_UN_SECRETO_LARGO_ALEATORIO"
allowed_emails = ["usuario1@empresa.com", "usuario2@empresa.com"]

[auth.google]
client_id = "CLIENT_ID_PROPORCIONADO_POR_GOOGLE"
client_secret = "CLIENT_SECRET_PRIVADO"
server_metadata_url = "https://accounts.google.com/.well-known/openid-configuration"

En Streamlit Community Cloud, configura los mismos valores desde App Settings >
Secrets, no subas secrets.toml a GitHub.

Para autorizar o retirar a una persona, el administrador modifica únicamente
la lista `allowed_emails` en Secrets y guarda los cambios. Usa cuentas
corporativas aprobadas y aplica el principio de mínimo privilegio.

La autenticación de la aplicación no convierte automáticamente el alojamiento
en infraestructura empresarial aprobada. Confirma con TI de CEMEX el proveedor,
la región, el tratamiento de datos, los registros, el respaldo y los controles.

8. CONFIDENCIALIDAD Y RESGUARDO
============================================================

El aviso que aparece en pantalla es una advertencia y una confirmación del
usuario; NO es un control técnico suficiente.

Medidas adicionales necesarias:
- Autenticación corporativa y lista de usuarios autorizados.
- Repositorio privado con MFA y permisos mínimos.
- Secretos fuera del repositorio.
- HTTPS y controles de red.
- Infraestructura y región aprobadas por CEMEX.
- Cifrado en tránsito y en reposo.
- Política de retención y eliminación de datos.
- Revisión de logs, telemetría, copias de seguridad y cachés del proveedor.
- Límites de tamaño de archivo y controles de acceso.
- No imprimir datos de SAP en logs o mensajes de error.
- No almacenar archivos cargados en disco ni compartirlos entre sesiones.

La aplicación mantiene el archivo cargado y el resultado en la memoria de la
sesión para permitir la vista previa y descarga. No escribe intencionalmente
el archivo en disco ni lo guarda en una base de datos. Aun así, el proveedor
de alojamiento controla parte de la infraestructura y sus políticas de
retención; esto debe revisarse contractualmente.

Streamlit Community Cloud no debe asumirse como entorno apto para datos
confidenciales de CEMEX. Para producción, prioriza una infraestructura privada
o empresarial aprobada por TI, por ejemplo Azure dentro del tenant corporativo,
AWS en una cuenta administrada por CEMEX o un servidor interno autorizado.

Con un archivo de prueba sintético:

- Un correo no autorizado no puede entrar.
- Los secretos no aparecen en GitHub.
- Los archivos originales no se guardan intencionalmente en disco.

Realiza además una comparación con el mismo archivo de prueba entre:
1. Predicciones del ensamble en Colab usando los codificadores originales.
2. Predicciones de la aplicación Streamlit.

Las categorías deben coincidir registro por registro en las filas válidas.

============================================================
10. LIMITACIÓN QUE DEBES TENER PRESENTE
============================================================

El modelo se entrenó con LabelEncoder en cuatro variables. Si un archivo mensual
contiene un valor que no existía en los datos de entrenamiento, la aplicación
lo marca como pendiente. No se debe entrenar un encoder nuevo con el archivo
mensual porque cambiaría la correspondencia entre códigos y categorías y
podría producir predicciones incorrectas.

Además, esta aplicación no reproduce toda la limpieza histórica ni las reglas
de reclasificación usadas para construir la variable objetivo. El modelo recibe
las cuatro variables explicativas originales y predice la categoría. Si SAP
cambia nombres de columnas, estructura o catálogo de valores, debe validarse
antes de clasificar.
